# 이미지등록 — 사진 ↔ 상품 자동 매칭 → RPA 등록

토스포스 매장의 "사진 넣어주세요" 요청을 처리한다. **조회(RPA) → 매칭(비전) → 등록(RPA)** 순서로, 신뢰도 높은 매칭만 자동 등록하고 애매한 건 검수로 뺀다. (메뉴 텍스트 등록은 [[메뉴판독]], 요청 적재는 대시보드 메뉴등록 카테고리 참고)

## 전제
- `rpa/` 셋업 완료 + 로그인 세션(`rpa/.auth/state.json`) 유효. 만료 시 `node rpa/login.js`.
- 이미지 파일 확보: 슬랙 첨부는 `slack_read_file`(비전 판독 겸용), 로컬 저장이 필요하면 담당자에게 다운로드 요청. 고객 Drive 링크는 접근 불가할 수 있음 → 슬랙 첨부 우선.

## 실행 절차

1. **상품 목록 조회** —
   ```
   node rpa/list-products.js --biz <사업자번호> --store "<상호명>" --out /tmp/products.json
   ```
   등록 상품 전체(이름·가격)가 JSON으로 나온다 (페이지네이션 자동 순회).

2. **사진 판독 & 매칭** — 실제 요청은 **캡션 없이 사진만 우르르** 오는 형태다. 열린 질문("이게 뭐지?")이 아니라 **1번 목록 안에서 고르는 닫힌 문제**로 풀어야 정확해진다.
   - 사진 전체와 상품명 목록을 **한 번에** 놓고 매칭한다. 한 장씩 따로 보면 비슷한 두 사진이 같은 상품에 배정되기 쉽다.
   - **사진 1장 = 상품 1개(1:1)**. 같은 상품에 여러 장이면 가장 선명한 1장만.
   - **추정 금지 원칙**: 확신 없으면 `low` + 후보 2~3개를 `note`에 표기. 매장 고유 상품명(예: "우리집 특제찌개")은 사진만으로 확정 불가 → `low`.

3. **매칭 결과 보고 & plan 저장** — 표(이미지 | 매칭 상품 | 신뢰도 | 비고)로 보고하고, 아래 형식으로 저장한다:
   ```json
   [ { "product": "현미바삭", "images": ["shots/a.jpg"], "confidence": "high", "note": "" } ]
   ```
   - `high` → 자동 등록 대상 / `low` → 담당자 선택 대기
   - 저장 후 형식 점검(브라우저 안 켬):
     ```
     node rpa/upload-images-batch.js --biz <사업자번호> --store "<상호명>" --plan <plan.json> --validate-only
     ```

4. **일괄 등록** — 로그인·매장 진입을 한 번만 하고 상품들을 순회한다(상품당 프로세스를 새로 띄우면 그 앞단 15~20초가 매번 반복된다).
   ```
   node rpa/upload-images-batch.js --biz <사업자번호> --store "<상호명>" --plan <plan.json>            # dry-run
   node rpa/upload-images-batch.js --biz <사업자번호> --store "<상호명>" --plan <plan.json> --confirm   # 실제 등록
   ```
   - **반드시 dry-run 먼저** → `rpa/shots/batch-*/` 스크린샷 검수 → 승인 후 `--confirm`
   - 담당자가 다른 업무를 병행해야 하면 `HEADLESS=true` 를 앞에 붙인다(창이 뜨지 않아 마우스·키보드를 뺏지 않음)
   - `low` 까지 올리려면 `--include-low` — 오등록은 수동 삭제해야 하므로 담당자 확인 후에만
   - 한 건이 실패해도 나머지는 계속 진행되고, `report.json` 에 등록/스킵/실패가 정리된다
   - 상품 하나만 급히 처리할 땐 기존 `upload-menu.js --product ... --images ...` 도 그대로 쓸 수 있다

5. **마무리** — `report.json` 기준으로 등록 N건 / 검수대기 N건 / 스킵 N건 요약. 슬랙 요청 건이면 처리 완료 리액션은 담당자 확인 후.

## 주의
- **테스트 먼저**: 새 매장 유형이면 첫 1건은 반드시 dry-run 스크린샷 검수 후 --confirm.
- 음식 사진만으로 메뉴명 추정은 한계가 있으므로 low 비율이 높으면 무리하지 말고 담당자에게 "사진별 메뉴명 캡션"을 요청하는 게 빠르다.
- 대량(10장+)일 때는 5장씩 끊어 실행하고 매 배치 스크린샷 확인 (봇 탐지·오류 파급 방지).
